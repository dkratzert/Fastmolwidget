# AGENTS.md — Fastmolwidget

Embeddable PyQt/PySide6 widget for crystal-structure display. Three parallel renderers (2D QPainter, Qt Quick QPainter, 3D OpenGL) share a single public API.

## Architecture (read these first)

- `src/fastmolwidget/__init__.py` — the *only* public surface; everything re-exported here is API.
- `molecule_base.py` — `MoleculeWidgetProtocol` (`@runtime_checkable`). Every renderer must satisfy it. New display methods MUST be added here too.
- `molecule2D.py` (`MoleculeWidget`) — pure-Python QPainter renderer; ORTEP ellipsoids, no OpenGL. Concrete `QWidget` subclass that mixes `MoleculeRendererMixin` with `QWidget`.
- `molecule_painter.py` (`MoleculeRendererMixin`) — Qt-base-class-agnostic mixin containing **all** 2-D rendering state and drawing logic (atoms, bonds, ADPs, hover, selection, PCA best-view). Both `MoleculeWidget` (2D) and `MoleculeQuickItem` (Quick) inherit from it; the concrete class only provides the Qt plumbing (`paintEvent`/`paint`, signals, `save_image`).
- `molecule_quick.py` (`MoleculeQuickItem`) — `QQuickPaintedItem` renderer that re-uses `MoleculeRendererMixin` inside a Qt Quick scene graph. Registered as the QML type `MoleculeItem` (module `Fastmolwidget 1.0`). Guarded by `_HAS_QTQUICK`; import never crashes when Qt Quick is missing.
- `molecule3D.py` (`MoleculeWidget3D`) — `QOpenGLWidget` with sphere/ellipsoid impostors and tessellated cylinder bonds. GLSL targets `#version 120` on macOS and `#version 140` on Windows/Linux. Must degrade gracefully when `PyOpenGL` is missing or context creation fails — see the `_HAS_PYOPENGL` guard at module top; never let the host app crash.
- `molecule3D.py` has priority now.
- `viewer_widget.py` / `viewer_widget3D.py` — `MoleculeViewerWidget` / `MoleculeViewer3DWidget` bundle a renderer + two-row control bar. Both expose `.render_widget` and `.load_file(path)`.
  - **Row 1** (both): Open File… button, Grow, Pack Unit Cell, Show ADP, Show Labels, Hide Hydrogens (`checked` → `show_hydrogens(False)`). Grow and Pack are mutually exclusive (toggling one unchecks the other).
  - **Row 2** (both): Bond Width spinbox (2D: 1–15, 3D: 0–15), Bond Color button (opens `QColorDialog`), Reset Rotation Center button → calls `render_widget.reset_rotation_center()`, Best View button (`align_best_view()`), Save Image… button (`save_image(...)`), a checkable Residual Density button and a Level `QDoubleSpinBox`, and a Parts filter (shown when multiple disorder parts are present).
  - Both viewers also expose a `.set_bond_color(color)` method that forwards to the renderer.
- `density_controls.py` — module-level, toolkit-agnostic helpers (`auto_reflection_file`, `ask_for_reflection_file`, `reflection_file_start_path`, `density_statistics_text`) used by **all three** viewers, plus `DensityControlsMixin`: the Residual Density button + Level spin box and their behaviour, shared by both viewer widgets (mixed in *before* `QtWidgets.QWidget`). Host contract: be a `QWidget`, create `self._render_widget` first, call `_init_density_controls()`, put the three widgets in the control bar, and call `_sync_density_controls()` after `load_file`. The button is disabled with an explanatory tooltip when `density.HAS_DENSITY_CPP` is `False`. Under `TYPE_CHECKING` the mixin's base is `QWidget` (at runtime it is `object`) so that parenting dialogs to `self` type-checks without a second `QWidget` in the MRO.
- `viewer_widget_quick.py` — `MoleculeViewerQuickWidget` / `MoleculeViewerBackend` bundle a `QQuickWidget` hosting a QML scene with the same two-row control bar as the widget viewers. `MoleculeViewerBackend` is a `QObject` exposed to QML as the context property `"backend"`; it owns the `MoleculeLoader` and forwards all QML controls to the `MoleculeQuickItem` render item. The QML scene lives in `qml/MoleculeViewer.qml`; the parts-filter dropdown is in `qml/PartFilterComboBox.qml` (opens a `Popup` upward to stay within the `QQuickWidget` bounds) and the residual-density level control in `qml/DensityLevelSpinBox.qml` (QtQuick's `SpinBox` is integer-only, so it stores hundredths of an e/Å³ and emits `levelEdited` from `onValueModified` — **user edits only**, which is what keeps the backend round-trip from looping). The viewer exposes `.render_widget`, `.load_file(path)`, `.set_bond_color(color)`, `.show_residual_density(...)` and `.clear_residual_density()`.
  - The backend's density controls mirror `DensityControlsMixin` but as QML-bindable properties (`densityAvailable`, `densityActive`, `densityLevel`, `densityLevelMin/Max`, `densityStatistics`) plus the `setDensity(bool)` / `setDensityLevel(float)` slots. `_set_density_active()` emits `densityActiveChanged` **unconditionally**: when showing the map fails, the QML button has already flipped itself to checked, so `False` must be pushed back out even though the backend's own state never changed. The reflection-file lookup is shared with the QWidget viewers through the module-level helpers in `density_controls.py` (`auto_reflection_file`, `ask_for_reflection_file`, `reflection_file_start_path`, `density_statistics_text`).
  - Gracefully degrades when Qt Quick is unavailable (`_HAS_QTQUICK` guard).
- `loader.py` (`MoleculeLoader`) — composition, not inheritance. Dispatch table `_FORMAT_MAP` maps suffix → method (`.cif`→`_load_cif`, `.res`/`.ins`→`_load_shelx`, `.xyz`→`_load_xyz`). To add a format: add an entry, implement `_load_<fmt>(self, path, *, keep_view)`, and (if it has symmetry) include the suffix in `_GROWABLE_FORMATS`. Also exposes `set_pack(enabled, symmop_indices)` for unit-cell packing (mutually exclusive with grow; pack takes priority). `load_file` also records the loaded path on the widget as `widget._model_path`, which `molecule3D.py` and `molecule_painter.py` need to compute residual-density maps.
- `hkl_io.py` — Qt-free readers for reflection data and SHELX refinement parameters: `read_shelx_hkl`/`parse_shelx_hkl` (fixed-format `HKLF 4` parsed column-wise with NumPy via `_parse_fixed_format`, per-line free-format fallback for anything irregular. The list is cut at the `0 0 0` terminator **before anything is converted** (`_terminator_row`, a character test on the three index fields), because SADABS appends its scaling report (`_exptl_absorpt_*`, `SADABS 2016/2: Krause, L., …`) to the file after it — that trailer is normal content, not damage, and 1 352 of 1 569 real `.hkl` files carry one. Files with **no** terminator can still hold stray lines — a CIF item that ended up inside a `_shelx_hkl_file` block, say — and a single one of those used to cost the whole file its vectorised parse; so if the conversion fails, records that cannot be fixed-format numbers are dropped via `_fixed_format_mask` (a character-class table lookup, the same records the per-line parser skips) and the conversion is retried once. Clean files never reach that retry: over a 2 149-file corpus the retry runs for 141 of them, all without a terminator), `read_cif_reflections` (fcf-style `_refln_*` loops, reuses `F_calc` when present), `read_cif_raw_reflections` (raw `_diffrn_refln_index_h/k/l` + `_diffrn_refln_intensity_net` + `_diffrn_refln_intensity_u`/`_sigma` + `_diffrn_refln_scale_group_code` — the *unmerged* measurements FinalCif and Olex2 write into the final CIF for checkCIF, i.e. an `HKLF 4` file in CIF clothing, merged downstream exactly like a `.hkl`), `embedded_shelx_hkl` (`_shelx_hkl_file` — self-contained SHELXL CIFs need no separate `.hkl`), and `read_shelx_parameters` → `ShelxParameters(osf, wght_a, wght_b, exti, wavelength, free_variables)`. Parameters are looked up in the order: the `.res`/`.ins` itself → a sibling `.res`/`.ins` of the same basename → a SHELX block embedded in the CIF (`embedded_shelx_res`, tags `_shelx_res_file` / `_iucr_refine_instructions_details`). `_data_blocks()` skips a leading `global_` block; **every** CIF reader here and in `density.py` must go through it. **All** CIF reads also go through `read_cif_document(path)`, a 2-entry cache keyed on path + mtime + size: one residual-density map needs the same (often multi-megabyte) CIF up to five times over. The returned `gemmi.cif.Document` is shared — treat it as read-only; `clear_cif_cache()` drops it.
  - `find_reflection_file(model)` / `has_reflections(path)` implement the automatic lookup: the model file itself first (embedded `_shelx_hkl_file`, a `_refln_*` loop, or a raw `_diffrn_refln_*` loop), then siblings of the same basename with a `_REFLECTION_SUFFIXES` extension (`.hkl`, `.fcf`, `.fco`, `.cif`). Within one CIF the sources are tried **in order of how processed they are** — `_refln_*` loop, then the embedded `.hkl` the refinement actually used, and only then the raw `_diffrn_refln_*` measurements, which are unmerged and unscaled and therefore the last resort. `has_reflections` is deliberately cheap — it never parses the reflections, only checks for the tags. **The viewer button is stricter than this**: `DensityControlsMixin._auto_reflection_file()` only accepts reflections *embedded in the model file* and otherwise opens the file dialog (pre-selecting a sibling `.hkl`), so it is always visible which dataset a map came from. The wider sibling search is only used by the programmatic `calculate_residual_density(model)` / `show_residual_density()` path.
- `density.py` — residual (Fo−Fc) maps, **Qt-free**. `calculate_residual_density(model, hkl=None)` → `ResidualDensityMap` (`.array` numpy grid over one unit cell, `.max/.min/.rms/.d_min/.scale`, `.isosurface(level, atoms=…, margin=…)` → Cartesian `(vertices, edges)` for `GL_LINES`). `hkl` defaults to the model itself, which is all a self-contained SHELXL CIF needs. Uses gemmi for the SF summation and FFT. **Performance of the interactive path** — a residual map is re-contoured on every level change, hydrogen toggle and disorder-part change, so this is not a cold path: `.isosurfaces(levels, …)` contours several levels from *one* cut-out of the grid (the two lobes share it, and `_region()`'s gather is tens of megabytes for a molecule spanning more than one cell), and both renderers ask for the two levels in a single call rather than calling `isosurface()` twice. The cut-out is the atoms' *bounding box*, which for anything but a compact blob is several times the volume actually wanted, so `_cube_mask()` describes the wanted part to `density_cpp.marching_cubes` as a coarse boolean mask over blocks of `CUBE_MASK_BLOCK` (8) cubes — each atom marks the block box covering its `margin` sphere, which is a conservative over-estimate, so no cube that could carry a wanted vertex is ever skipped and the surface is **exactly** the one an unmasked run gives (pinned by `test_cube_mask_does_not_change_the_surface`). Skipped blocks are never read at all: for `41467_2015_BFncomms9288_MOESM1369_ESM.cif` that is 71 % of an 11.2 M-voxel box, 0.19 s → 0.046 s, and 126 k vertices → 33 k. What is left is then clipped exactly by `_clip_to_atoms`, which rejects most of the remainder up front with `_clip_candidates`: the buckets holding atoms are marked in a small boolean grid and grown by one cell (`_dilated`), so a vertex whose own bucket is not in that set is provably farther than `margin` from every atom and never reaches the 27-offset distance search. `_apply_extinction` is likewise evaluated over the whole reflection array (`calculate_d_array`) instead of per reflection. Three non-obvious requirements when building a `gemmi.SmallStructure` by hand — all three silently give wrong results if missed: (1) `site.element` must be set (`type_symbol` is only a label, otherwise everything scatters as `X`); (2) `structure.setup_cell_images()` must be called (the SF calculator reads symmetry from `UnitCell`, not from the space group); (3) CIF-read structures need `change_occupancies_to_crystallographic()`. Map coefficients follow SHELXL's own convention: unweighted `(|Fo|/OSF − |Fc|)·exp(iφc)` — `WGHT` is *not* applied to Fourier coefficients. On top of that, **weak data is down-weighted** as the only smoothing: each coefficient is multiplied by `1/(1 + w·(σ(F)/|Fc|)³)` (`_weak_data_damping`, `DEFAULT_WEAK_WEIGHT = 1.0`, `WEAK_DATA_EXPONENT = 3.0`, `weak_weight=0.0` disables it). It is a reciprocal-space, data-driven low-pass filter — never blur the finished grid, that would displace features. `_merge_to_asu` therefore returns `(hkl, |Fo|, σ(F))`, with σ propagated onto the amplitude scale as `sqrt(F² + σ(F²)) − |Fo|`; both σ and |Fo| are divided by the scale factor before being compared with `|Fc|`. The filter is skipped when `ReflectionData.sigma_known` is `False` (an fcf-style CIF with no σ column, where σ is a placeholder).
  - **Grid size is fixed by the cell, not the data**: `_grid_size()` divides the cell edges by `DEFAULT_GRID_SPACING` (0.15 Å — chosen so individual residual-density features keep their shape; coarser grids look blocky once contoured) and rounds up to a 2/3/5/7-smooth FFT size, then `_fits_in_grid()` drops reflections beyond `(n-1)//2` so nothing aliases. `exact_size` (not `min_size`/`sample_rate`) is passed to gemmi, otherwise high-resolution data silently enlarges the grid.
  - **Two data defences that matter a lot**: systematically absent reflections are dropped in `_merge_to_asu` (vectorised: `GroupOps.systematic_absences` + `_equivalence_classes()` labelling symmetry orbits in NumPy + `np.bincount`, with one `ReciprocalAsu.to_asu` call per *unique* reflection rather than per observation) (their `Fc` is 0, so their noise enters the map multiplied by `1/scale`), and `_sanitise_adps()` downgrades non-positive-definite ADP tensors to isotropic with a `RuntimeWarning` (a negative eigenvalue makes the Debye-Waller factor grow with resolution — `tests/test-data/p21c.cif` has exactly this defect on `Al1` and without the guard the map peaks at ±9 e/Å³ instead of ±1.3).
  - **SHELX symmetry**: `_shelx_spacegroup()` must combine the `SYMM` cards with the `LATT` **centring translations** (`_LATT_CENTRING`) and, for a positive `LATT`, an inversion centre. Using the `SYMM` cards alone silently produces a primitive subgroup (C2/c → P2/c), which halves the symmetry mates and makes every Fc wrong — it showed up as a residual map peaking at +31 e/Å³ instead of +0.5.
  - **Twinning and re-indexing**: `_apply_hklf_transform()` handles the full `HKLF N S r11…r33 sm` card — the index matrix (`h' = r11·h + r12·k + r13·l`, positive determinant enforced) is applied *before* anything else, because the cell, symmetry and coordinates in the `.res` refer to the transformed indices. `_detwin_observations()` then splits twinned intensities using `Fo²(h₁) = Io · |Fc(h₁)|² / Σ_k b_k |Fc(h_k)|²`. `HKLF 4` + `TWIN` generates the other domains from the twin law (`_detwin_hklf4`, fully vectorised — every record has the same number of components, so the whole data set is one `(N, components, 3)` index block); `HKLF 5` reads them from the file, where consecutive records ending in a *positive* component number form one observation (`_hklf5_groups`). A **negative** `TWIN` count means general *and* racemic twinning: `|n|` components, the matrix generating `1…m` and `m+1…2m` being their Friedel opposites. Absent `BASF` means 'perfect' twinning (equal fractions). `HKLF 5` may not be combined with `TWIN`, so **the declared format alone selects the layout** — a negative batch number in `HKLF 4` data is an *R*free flag, not an overlap marker, and must never be treated as one. Without detwinning a twinned refinement's map is several times too large (`Esser_JW316`, `BASF 0.35`: rms 0.21 → 0.05 against SHELXL's 0.04). **Never ask gemmi for `|Fc|` one Miller index at a time here**: detwinning needs it for every component of every observation (over a million lookups for a real data set) and the per-index route cost 18 s of a 20 s map. `_domain_intensities()` folds the indices onto Friedel pairs (`|Fc(−h)| = |Fc(h)|` exactly, because the addends are real — phases are *not* preserved, so the map coefficients themselves must never be folded this way), reduces them to the distinct ones with `_unique_index_map()` (the three components packed into one `int64` key, so it is a 1-D `np.unique` rather than the much slower `axis=0` variant) and makes a single batched `_summed_structure_factors` call.
  - **Racemic twins are a no-op** in the detwinning maths: `h` and `−h` differ only through *f″*, which gemmi's real-valued addends cannot express, so the map stays marginally too large. Documented, not worked around.
  - **SHELX negative `U_iso`** (`-1.5` = 1.5 × U_eq of the pivot atom) is still resolved in `small_structure_from_shelx`: *shelxfile* v25 returns the raw `-1.5` from `uvals` and a meaningless negative `ueq` for riding atoms. Occupancies, by contrast, are taken straight from `atom.occupancy` — v25 decodes the SOF free-variable codes correctly (this needs `shelxfile>=25`; v24 mis-decoded negative SOFs with a site-occupancy factor ≠ 1 and dropped riding atoms' SOFs).
- `fastmolwidget/density_cpp` (`src/fastmolwidget/density_cpp/density_cpp.cpp`) — optional pybind11 marching-cubes extension, built by `setup.py` alongside `sdm_cpp` and imported as `from fastmolwidget import density_cpp`. `marching_cubes(grid, level, origin, step, mask=None, block=8) -> (vertices, edges)` with deduplicated wireframe edges. `mask` is an optional coarse boolean array with one entry per `block`×`block`×`block` cubes (shape `ceil((n-1)/block)`); cubes in an unset block are skipped and their density is never read, while the iteration order is unchanged so the vertices are numbered exactly as an unmasked scan restricted to the same cubes would number them. Note that a *sign-reduction* pre-pass (classifying every cube as all-above / all-below / mixed in one sweep, to skip the uniform ones) was tried and is **slower**: the eight corner reads per cube are cache-resident anyway, so the extra passes over an 11 M-voxel byte array cost more than they save. Skipping regions wholesale is what pays. Also `structure_factors(...) -> complex128[N]`, a vectorised port of gemmi's `StructureFactorCalculator` that tabulates the separable phase factor `exp(2πi(hx+ky+lz))` over the Miller-index range (two complex multiplies per term instead of a sin/cos pair — ~15× faster; gemmi's own direct summation is documented as deliberately unoptimised and its FFT route needs a macromolecular `Model`, not a `SmallStructure`). `density._summed_structure_factors` falls back to gemmi when the extension is absent or an element has no IT92 parametrisation, so `Fc` is always defined. The phase tables are stored **Miller-index major** (all site-images of one `h` contiguous) so a reflection reads three contiguous runs instead of striding through the whole multi-megabyte table; for a 1530-site model that layout alone is worth ~30 %. Both are described by `src/fastmolwidget/density_cpp.pyi`; keep the stub in step with the bindings. Guarded by `density.HAS_DENSITY_CPP`, which checks `hasattr(density_cpp, 'marching_cubes')` rather than just the import — a bare import can succeed against a stale or unbuilt module. There is **no** pure-Python fallback: the feature raises a clear `RuntimeError` and the viewer disables its button instead. Tests must `importorskip("fastmolwidget.density_cpp")` (the fully qualified name), otherwise they silently skip.
- `sdm.py` — Shortest-Distance-Matrix algorithm to grow asymmetric units to whole molecules. Optional C++ acceleration via `import sdm_cpp` (`HAS_CPP` flag); the Python path must keep working. `SDM.calc_sdm` mutates its input atom list — always pass a fresh copy (see `_compute_grown_atoms`). Also provides `SDM.pack_unit_cell(symmop_indices)` for unit-cell packing (does not require `calc_sdm` to have been run first).
- `cif/cif_file_io.py` — `CifReader` (uses `gemmi`) yields `Atomtuple` via `.atoms_orth` / `.atoms_fract` and ADPs via `.displacement_parameters()`.
- `atoms.py`, `dsrmath.py`, `tools.py` — element radii/colours, vector/matrix helpers, `to_float` for CIF strings (strips esd parentheses).

## Core data type

`Atomtuple = namedtuple('Atomtuple', ('label','type','x','y','z','part','symm_matrix','adp'), defaults=(None, None))` (defined in `sdm.py`). Coordinates are Cartesian Å when fed to widgets; `part` is SHELX disorder part. `adp` is `(U11,U22,U33,U23,U13,U12)` or `None` for isotropic atoms — embedded directly in the tuple. `cell` is `(a,b,c,α,β,γ)`.

## Conventions

- **Qt binding-agnostic**: always `from qtpy import ...`; never import `PySide6` / `PyQt6` directly. Stubs use `pyside6-stubs`.
- **3D fallback path**: any code path in `molecule3D.py` that touches `gl.*` must be guarded so the widget reverts to a `QWidget` text overlay instead of raising.
- **Growing structures**: enabled via `MoleculeLoader.set_grow(True)`; reloads the last file in-place with `keep_view=True`. XYZ has no symmetry → grow is a no-op.
- **Packing structures**: enabled via `MoleculeLoader.set_pack(True)`; applies all (or selected) symmetry operations and folds atoms into one unit cell. Pack takes priority over grow when both are active.
- **Public API additions** must be reflected in: the relevant widget class, `MoleculeWidgetProtocol`, `__init__.py` `__all__` (**and** its `_LAZY_IMPORTS` map + `TYPE_CHECKING` block — the top-level package imports lazily), and `README.md`. Current protocol methods: `open_molecule`, `clear`, `show_adps`, `show_labels`, `show_hydrogens`, `set_visible_parts`, `set_bond_width`, `set_bond_color`, `set_labels_visible` (alias for `show_labels`), `set_background_color`, `setLabelFont`, `reset_view`, `align_best_view`, `set_model_source`, `has_residual_density_data`, `show_residual_density`, `set_residual_density_level`, `clear_residual_density`, `refresh_residual_density`, `residual_density_map`, `residual_density_level`, `save_image`. `Atomtuple`, `ModelSourceMixin`, `MoleculeQuickItem`, `MoleculeViewerBackend`, `MoleculeRendererMixin`, `ResidualDensityControls`, `ResidualDensityMap`, `calculate_residual_density`, `ReflectionData`, `ShelxParameters`, `read_reflections`, `read_shelx_parameters`, `bundle_js`, `structure_json`, `render_html`, and `write_html` are exported in `__all__`.
- **`shelxfile`** is a required runtime dependency (used in `loader.py` for `.res`/`.ins`); it is listed in `pyproject.toml` `dependencies`, not in extras.
- **3D mouse controls**: left-drag rotate, right-drag zoom, middle-drag pan, **middle-click recentres the rotation pivot** on the clicked atom (`reset_rotation_center()` restores the default), scroll-wheel adjusts label font size.
- **Ctrl + scroll wheel** (2D and 3D) steps the residual-density contour level via `step_residual_density_level(±1)`; one step per wheel *event*, `DENSITY_LEVEL_STEP` (0.02 e/Å³) each, clamped to `DENSITY_LEVEL_MIN`/`DENSITY_LEVEL_MAX` — all three live in `molecule_base.py` and are also what `density_controls.py` gives the Level spin box, so the two can never disagree. The event is `ignore()`d when no map is loaded, so it is not silently swallowed. `set_residual_density_level` emits the **`densityLevelChanged(float)`** signal (only on a real change); `DensityControlsMixin._on_density_level_changed` mirrors it into the spin box with `blockSignals`, which is what stops the spin box ↔ renderer round-trip from looping. Any new renderer must declare that signal alongside `atomClicked` / `bondClicked` / `partsChanged`.
- **Keyboard shortcuts** (both 2D and 3D, requires unit cell): **F1** aligns the view so that real-space axis **a** points towards the viewer (i.e. the b–c face is seen flat-on); **F2** → **b**; **F3** → **c**. For orthogonal cells this is the same as aligning along the reciprocal axis; for non-orthogonal cells it correctly places the chosen cell edge perpendicular to the screen. No-op when no cell is loaded. A unit-cell axis indicator (a=red, b=green, c=blue) is drawn in the bottom-left corner while Pack Unit Cell is active.
- **No new top-level deps** without updating `pyproject.toml` extras (`pyside6`, `pyqt6`, `gl3d`, `cpp`, `density`).
- **Residual density (all three renderers)**: `show_residual_density(hkl_path=None, level=None, *, model_path=None)`, `set_residual_density_level(level)`, `clear_residual_density()` and the `residual_density_map` / `residual_density_level` properties live on `MoleculeWidget3D` **and** on `MoleculeRendererMixin` (so 2D and Qt Quick get them too). Never re-add no-op stubs on `MoleculeWidget` / `MoleculeQuickItem`: a method defined on the concrete class shadows the mixin. `hkl_path=None` (the default) resolves the reflections via `hkl_io.find_reflection_file`; the viewer button, however, only auto-uses reflections embedded in the model file and opens a dialog for everything else (see `hkl_io.py` above). `level=None` contours at `density.DEFAULT_SIGMA` (3.0) × the map RMS via `ResidualDensityMap.sigma_level()` — a fixed absolute level is wrong here, because the RMS of a residual map varies by an order of magnitude between structures. The viewer pushes the resulting value into the Level spin box. The viewer's button is **checkable** and is the single source of truth for the on/off state — `_on_density_toggled` pops it back out on any failure (no model, no data, cancelled dialog) — while `show_/clear_residual_density` push the state back into it via `_set_density_controls_active()`, which also enables/disables the Level spinbox.
  - **Lifetime**: `MoleculeLoader.load_file` calls `widget.set_model_source(path)` before loading; `ModelSourceMixin` (in `molecule_base.py`) clears the density only when the source really changes — paths are compared by value, so reloading the *same* path (what grow and pack do) keeps the map, and `_load_molecule` then re-runs `_build_density_geometry()` so the surface is re-clipped around the new atom set. Hosts that feed atoms through `open_molecule()` declare their own sources with `set_model_source(model, reflections)` (path, `gemmi.cif.Document`/`Block` or `gemmi.SmallStructure`), ask `has_residual_density_data` before offering the feature, and can call `refresh_residual_density()` after changing the displayed atoms themselves. `density_controls.DensityControlsMixin.allow_reflection_dialog = False` suppresses the file-dialog fallback (silently skips instead), `update_density_availability()` greys the button out when there is no data, and `ResidualDensityControls` is the same button + Level spin box as a standalone widget for hosts with their own layout. `MoleculeViewer3DWidget.load_file` calls `_sync_density_controls()` afterwards so the button never claims density is shown when it is not. `show_/clear_residual_density` are part of `MoleculeWidgetProtocol`. **2D / Qt Quick rendering** (`molecule_painter.py`): the same `isosurface()` output is stored as `(K, 2, 3)` line segments in the *unrotated model frame* (`_density_pos_lines` / `_density_neg_lines`) and projected in `draw()`, so rotating never re-contours. Because the mixin rotates `Atom.coordinate` / `_coords_array` **in place** about a `molecule_center` that itself moves (pan, middle-click recentre), the model→view mapping is tracked explicitly as `_view_rotation` / `_view_offset` (`view = model @ R.T + t`): every site that rotates `_coords_array` — `_load_molecule` (keep_view), `rotate_molecule`, `align_best_view`, `_align_to_reciprocal_axis` — **must** also call `_apply_view_transform(M)`, and `_model_coords_array` keeps the unrotated coordinates the surface is clipped against. The cage is drawn after the atoms and bonds, with viewport and sub-pixel culling and a reused `QLineF` buffer (allocating thousands of Qt objects per repaint is the bottleneck, not the rasterisation). **3D rendering** uses `shaders.LINE_VERT/LINE_FRAG` and one shared VBO holding both lobes (positive lobe first, `_density_pos_count` indices, then the negative lobe), drawn as `GL_LINES` after the solid geometry. The surface is clipped to `DENSITY_MARGIN` (1.5 Å, defined in both `molecule3D.py` and `molecule_painter.py`) around `_visible_atom_positions()` / `_visible_model_positions()` — the atoms actually drawn, i.e. after the hydrogen and disorder-part filters — so `show_hydrogens()` and `set_visible_parts()` re-contour the density (cheap; the map itself is cached and not recomputed).
  - **In-memory sources**: `density.calculate_residual_density(model, reflections)` and every CIF reader in `hkl_io.py` accept a path, a `gemmi.cif.Document` or a single `gemmi.cif.Block` (`CifSource`); reflections additionally accept ready `ReflectionData` (`ReflectionSource`). The block-level readers (`read_block_reflections`, `block_has_reflections`, `block_shelx_hkl`, `block_shelx_res`, `block_shelx_parameters`, `density.small_structure_from_block`) hold the actual logic and the path variants are thin wrappers over `_cif_blocks()`. An in-memory model has no directory to search, so its reflections must be inside it or passed explicitly.
- Python 3.12+ syntax (`X | None`, `from __future__ import annotations` is used widely). Per repo policy assume Python 3.14, PyQt5 *only when explicitly editing user code*; library code stays on `qtpy` + Python ≥ 3.12.

## JavaScript renderer & web export (`src/fastmolwidget/web/`)

A dependency-free browser/Canvas port of `molecule2D.py` + `molecule_painter.py`
plus the SDM grow/pack-unit-cell logic (`sdm.py`), for embedding molecule
views in web pages without Qt. CIF/SHELX file **parsing** still happens in
Python (`fastmolwidget.web_export` exports the asymmetric unit + symmetry
ops as JSON); growing, packing, and rendering all run in the browser. All
algorithmic ports were numerically cross-validated against the real Python
implementations (see `src/fastmolwidget/web/js/README.md` "Notes on fidelity",
which also documents the file layout, JSON contract and API mapping).

- `web/js/` — the ES modules, shipped as package data (`pyproject.toml`
  `[tool.setuptools.package-data]`). `index.js` is the public entry point;
  `embed.js` provides `createViewer(container, structure, options)` and the
  shared control bar.
- **Residual density in the browser**: the map is computed in Python and
  embedded in the page — `web_export.export_density(model, hkl=None, *,
  level, grid_spacing=0.25, margin=1.5, coverage='asu'|'grow'|'cell',
  compress=True)` ships **one whole unit cell** (periodic, so JS can wrap it
  around grown/packed molecules), int8-quantised against the full data range,
  zeroed outside `margin + 2 grid steps` of the covered atoms, gzipped and
  base64'd. Masking that way is **exactly lossless for the contour** (verified
  in `tests/test_web_density.py`) and cuts the payload 3-4x; the 2-step slack
  is what makes it lossless, since marching cubes needs the full cube around
  any cell holding a vertex. It is strictly **opt-in**: no `density=` argument
  means no `density` JSON key and no size change. `js/mc_tables.js` builds the
  256-case tables at load time by porting `build_lookup_tables()` from
  `density_cpp.cpp`, so `js/density.js` `marchingCubes()` reproduces the C++
  cage vertex for vertex — do **not** replace it with a different
  marching-cubes flavour without accepting that the browser and Qt cages
  diverge. `DensityMap.fromPayload()` is **async** (`DecompressionStream`), so
  `MoleculeViewer2D.setDensityVisible()` is too and resolves to whether the
  surface really went up. `molecule2d.js` mirrors `molecule_painter.py`: model-
  frame segments plus `_viewRotation`/`_viewOffset`, updated in the single
  `_applyDeltaRotation()` choke point (Qt needs four call sites).
- `web/assets.py` — `importlib.resources` access to the shipped JS/templates.
- `web/bundle.py` — `bundle_js()` turns the ES modules into **one classic
  `<script>` blob** defining `window.Fastmolwidget` (a CommonJS-style module
  registry inside an IIFE). It only understands the static named
  `import`/`export` syntax used in `web/js/` and raises
  `UnsupportedJsSyntaxError` on anything else — including import cycles — so a
  JS change can never silently produce a broken bundle. Result is cached
  (`bundle_js.cache_clear()` in dev servers).
- `web/templates/viewer.html` — the standalone page, rendered with
  `string.Template` (`$placeholder`), **not** `str.format`/f-strings (literal
  CSS/JS braces) and **not** Jinja2 (no runtime dependency).
- `web/html.py` — `structure_json()` (escapes `<`/`>`/`&` as `\uXXXX` so it
  stays valid JSON *and* a safe `<script>` payload) and
  `render_html()` / `write_html()` for a fully self-contained page.
- `web_demo_server.py` — threaded dev server serving that page plus the raw ES
  modules.
- **`fastmolwidget.web` must never import Qt.** `fastmolwidget/__init__.py` is
  therefore lazy (:pep:`562` `__getattr__`), so report generators can use the
  web helpers without a Qt binding installed. Keep it that way when adding
  exports.
- JS is bundled at runtime from the packaged sources (no build step), so an
  editable checkout always reflects the current JS.
- `tests/test_web_bundle.py` executes the bundle with Node.js when available
  (skipped otherwise) and cross-checks `SDM.grow()`/`packUnitCell()` against the
  Python `SDM`.
